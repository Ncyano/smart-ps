# 项目知识库（Agent Wiki）

> 这不是给人看的文档，是给**接手的 AI / 新同事**看的上下文包。
> 目标：新会话开局 3 分钟内搞清楚「这个项目在做什么、踩过哪些坑、有哪些现成资产」，不必重走弯路。

## 怎么用

**如果你是新开一个会话的 AI 助手：**

1. 先读 `00-项目上下文.md`（3 分钟，一页看懂全局）
2. 接到任务后按类型查 `02-工艺路线.md`（决策树：这类图该用什么做法）
3. **动手前必读** `03-踩坑库.md` 里对应章节（这个项目 80% 的时间浪费在重复踩坑）
4. 需要具体参数 → `04-参数与阈值.md`
5. 需要找现成脚本/产出 → `05-资产索引.md`
6. 看到不认识的词 → `06-术语表.md`

**不要求通读。** 每篇文件顶部都有「什么时候读」，按需跳。

**检索**（零依赖，纯标准库）：

```bash
python scripts/kb_search.py "错位"              # 关键词检索，返回最相关的段落
python scripts/kb_search.py "倒影 羽化" -n 8    # 多关键词，取前 8 条
```

## 三条最重要的结论（先记住这三条）

**1. 不要让生成模型画文字。**
模型画瓶标会出乱码、画价格会糊、画卖点会冒出违禁成分名（真实踩过 `MARYANUM (Cannabis Sativa)`）。
所有文字一律由 PIL / HTML 后置绘制。这是本项目的第一原则，`项目方案.md` §6 也这么写的。

**2. 贴屏类合成，对齐只占 20%。**
剩下 80% 是亮度关系、清晰度匹配、环境反射、边缘过渡。四角标得再准，光影不对就是"贴纸"。
判断标准：缩小到 30% 看，若一眼能指出屏幕轮廓，就是失败。

**3. 连续两轮「微调同一处还对不上」，立刻停止调参，换测量手段。**
这个项目在大屏上浪费了 5 轮，全都是用目测估坐标（每次偏差 10–40px）。后来改用「阈值分割 + 逐边 RANSAC 拟合」一次解决。

## 维护约定

- 新踩的坑**当天**写进 `03-踩坑库.md`，格式：`症状 / 根因 / 解法 / 一句话教训`
- 参数改了要同步 `04-参数与阈值.md`，否则下次接手的人会按旧值调
- 新增脚本写进 `05-资产索引.md`，注明入口和依赖
- 这份库和 `docs/` 分工：`docs/` 是对外的设计文档，这里是对内的**实战记忆**
