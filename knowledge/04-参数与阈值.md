### 1.2 融合参数

| 参数 | 地铁 | 商场 | 含义 | 调大/调小的后果 |
|---|---:|---:|---|---|
| `lift` | 9.0 | 9.0 | 黑位抬升（发光底噪） | ↑ 屏内发灰；↓ 死黑像贴纸 |
| `env` | 0.080 | 0.085 | 场景强模糊的环境漫反射 | ↑ 细节被冲淡 |
| `ambient` | 0.032 | 0.032 | 全局背光透射 | ↑ 整块发灰（最危险） |
| `gamma` | 1.0 | 1.0 | 中间调提亮 | 0.7–0.9 会亮但保持黑位 |
| `blur_kv` | 0.75 | 0.8 | 贴图前景深模糊 | ↓ 到 0 = 一眼假（锐利贴纸） |
| `tex` | 1.9 | 2.0 | 摩尔纹+像素噪声强度 | ↑ 噪点脏 |
| `refl` | 0.07 | 0.07 | 玻璃环境倒影叠加 | ↑ 像反光玻璃；↓ 像哑光纸 |
| `spill` | 0.55 | 0.50 | 光溢出到周围墙面 | ↑ 边框发亮 |
| `backlight` | 0.10 | 0.10 | 背光衰减强度 | ↑ 边缘过暗 |
| `backlight_span` | 0.09 | 0.10 | 衰减影响范围（占 min(W,H)） | — |
| `edge_dark` | 0.82 | 0.82 | 最边缘亮度系数 | ↓ 出现暗边框 |
| `edge_w` | 3.0 | 3.0 | 边缘压暗宽度(px) | ↑ 边缘发暗一圈 |
| `band` | 0.03 | 0.03 | 顶部灯管反射带 | ↑ 出现明显亮条 |

### 1.3 遮罩参数（最容易搞错的两项）

| 参数 | 值 | 说明 |
|---|---:|---|
| erode | **0**（不腐蚀） | 内缩 4px = 四边各漏一条原画面 |
| 羽化 sigma | **0.6px** | 1.3–2.6px 会让亮面板透出来，形成漏光线 |

## 二、地面倒影（`产出/需求样张/_floor_reflect.py`）

## 五、保真分档阈值（`server/app/pipeline/fidelity.py`）

阈值不在 `config.toml` 里，在代码顶部常量——因为它和实现强绑定，
改完必须跑 `scripts/bench_fidelity.py`（15 个已知该过/该拦的样本）。

| 常量 | 值 | 含义 |
|---|---:|---|
| `TIER_A_STRUCTURE` | 0.72 | 结构分 ≥ 此值才有资格拿 A |
| `TIER_C_STRUCTURE` | 0.40 | 低于此值判 C（产品不在/被替换） |
| `TIER_A_SPREAD` | 0.15 | A 档的比例容差 |
| `TIER_B_SPREAD` | 0.25 | 超过则加一条"建议核对" |
| `TIER_C_SPREAD` | 0.32 | 超过判 C（明显变形） |
| `TIER_SHARP` | 0.65 | 主体区清晰度低于此值判 C |
| `PATCH_B.structure` | 0.45 | 多实例场景下，块匹配 ≥ 此值给 B |

### 语义判定（`[quality] judge`，见 `pipeline/judge.py`）

| 键 | 值 | 说明 |
|---|---|---:|
| `judge` | `"auto"` | `auto` = 有可用模型就启用；`off` = 强制关闭 |
| `judge_model` | `""` | 留空按 `CANDIDATES` 顺序自动挑第一个能通的 |
| `judge_max_side` | 768 | 送图长边，越大越准也越贵 |

候选模型（按便宜排序）：`doubao-seed-2-1-lite-260915` → `doubao-seed-2-1-turbo-260628`
→ `doubao-seed-2-0-lite-260428` → `doubao-seed-2-1-pro-260915`。
**当前已开通 `doubao-seed-2-1-lite`**，实测 5–15s/张、约 0.002 元/张。

> ⚠️ `aspect_ok` **不可信**：17% 压扁、25% 拉长它都说"比例正常，把握 98"。
> 只作提示用（判 false 最多降 B），永远不用它单独判 C。
> 细节见 `knowledge/07-待决事项.md` §2 与 `pipeline/judge.py` 顶部的能力表。

**实测分布**（`bench_fidelity.py` 输出，可作为回归基准）：

| 样本 | 结构 | 比例 | 清晰 | 档 |
|---|---:|---:|---:|---|
| 原图（白底基准） | 1.000 | 0% | 1.00 | A |
| 换背景+挪位+缩到 28% | 0.853 | 2% | 1.68 | A |
| 换背景+偏左下 45% | 0.632 | 0% | 1.20 | B |
| 换背景+调色+锐化 | 0.512 | 8% | 0.93 | B |
| 纵向压扁 17%（减重） | 0.487 | 13% | 1.54 | B |
| 横向拉长 25% | 0.555 | 15% | 1.52 | B |
| 旋转 90° | 0.582 | 197% | 0.12 | C |
| 主体被抹掉 | 0.266 | — | 0.06 | C |
| 严重模糊（6px） | 0.555 | 10% | 0.50 | C |
| 主体被裁掉一半 | 0.482 | 45% | 0.90 | C |
| 真实 Seedream 候选 ×4（工厂素材） | 0.57–0.61 | 未校验 | 未校验 | B |
| 空白场景 | 0.220 | 未校验 | 未校验 | C |

**为什么压扁 17% 只给 B 而不是 C**：`spread` 靠"离背景色多远"分割主体，
而产线每张图都会过 `tone_match` 调色，调色本身就能让这个量漂 10–13%
（等于原图的 mock 产物被报"拉长 12%"）。所以 10–20% 区间不下结论。
宁可 B 让人看一眼，也不假装量准了——旧版正是把这张判成 0.997 放行。

## 五之二、品类一致性（`server/app/pipeline/category.py`）

这一层不产出分数，只做**拦截**：文案与产品品类冲突时，在生成前抛
`CategoryError`（HTTP 400），一分钱不花。

**词表三类，强度不同**

| 类 | 例 | 用途 |
|---|---|---|
| 使用动作（强） | 上脸、上妆、遮瑕、持妆、卡粉、浮粉、奶油肌 | 命中即判 `skincare` |
| 明确品类名（强） | 面霜、气垫、粉底、精华、乳液、面膜 | 命中即判 `skincare` |
| 剂型/服用（强） | 每天一粒、每粒、软胶囊、吞服、口服液、`\d+粒装` | 命中即判 `oral` |
| 效果词（**弱，不定性**） | 保湿、补水、提亮、抗皱、修护、控油 | 只记录，不判 |
| 成分词（**弱，需剂量**） | 辅酶、鱼油、益生菌、维生素 | 配合 `\d+mg` 才升级为 `oral` |

**关键常量**

| 项 | 值 | 说明 |
|---|---|---|
| `_DOSE_RE` | `\d+(\.\d+)?\s*(mg\|毫克\|μg\|微克\|iu)` | 剂量标记 |
| `_PILL_RE` | `\d+\s*粒(装\|瓶\|盒)?` | "60 粒装"这类，词表列不全靠正则兜 |
| 素材品类判定 | `cosmetic` / `edible` / `other` | `other` **不参与**冲突判定（不瞎猜） |
| 拦截时机 | ③.5（生成之前） | 文案错了后面全是废图 |

**成本与耗时**：一次视觉模型调用约 0.003 元、8–16s；
用户显式声明品类（`category=skincare`）时不调模型；
文案无品类倾向时不调模型（无对照物，看了也不会冲突）。

## 六、批量生成压测（`scripts/bench_*.py`）

```bash
python scripts/bench_local.py --rounds 10 --candidates 3 --engine seedream
python scripts/bench_score.py        # 统计评分分布
python scripts/bench_demands.py      # 按需求类型跑
```

10 轮真实 Seedream 实测结论：
- 模型名必须带日期后缀
- `n` 参数无效（恒回 1 张），多候选必须并发
- 内容安全无兜底（违禁词会直接过）
