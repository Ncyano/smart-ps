### 2. `fidelity` 评分器方向是反的 —— ⚠️ 部分解决（2026-11-26）

**现象**：换背景（应该低分）得 0.799 被拦；减重 17%（应该高分）得 0.997 放行。
**根因**：整图 96×96 灰度相关，比的是"和原图构图像不像"，而本项目专门改构图。

**已做**：换成 `pipeline/fidelity.py`——主体模板匹配（掩码加权 NCC）+ 匹配框内量比例
+ 主体区域清晰度，输出 A/B/C 三档而不是一个假精确的小数。15 个样本（真实候选 +
可控负样本）全部判对，见 `scripts/bench_fidelity.py`。

**仍然做不到**：

| 想判的 | 为什么做不到 | 出路 |
|---|---|---|
| 10–20% 的细微比例改动 | 产线每张都过 `tone_match`，调色会让"离背景色多远"整体漂 10–13% | 只能给 B 让人看 |
| "是不是同一款产品"（换包装/换logo） | 这是语义问题，相关系数答不了 | 视觉模型 |
| 文案/Logo 有没有乱码 | 同上，需要 OCR 或视觉模型 | 视觉模型 / OCR |

**视觉模型已接通，但只补上了一半**：`server/app/pipeline/judge.py` 已接入
`doubao-seed-2-1-lite-260915`（Key 已开通 seedream + 该模型）。

实测能力：

| 用例 | 同一款 | 比例 | 把握 |
|---|---|---:|:--:|
| 真实候选 / 空白场景 / 无关真人图 | ✅ 判对 | — | 98–100 |
| 纵向压扁 17%、横向拉长 25%、旋转 90° | 漏（都说 true） | **漏** | 98 |

**所以还剩一条真的没解决**：细微比例改动（10–30%）现在没有任何手段能自动发现。
`spread` 只能抓 >32%，视觉模型看不出 17%，且它会给 98 的把握——比不判更危险。

**可能的出路（未验证）**：
1. 素材若是白底图，改用"轮廓面积/周长"这类几何量，对调色不敏感
2. 用分割模型（SAM 类）拿干净掩码，再量比例——本地没有，要装
3. 让生图时直接要求"保持原始宽高比"，从上游消掉这个问题（最省事）

**已经成立的部分**：换错产品/产品没进画面，现在能自动拦到 C，置信度 98–100。

### 5. 四角仍需逐场景手工标定

`QUAD_MALL` / `QUAD_METRO` 是硬编码的实测值。换一张场景照片就要重新标。
**修法**：把「阈值分割 + 向外扫暗线 + RANSAC」封装成 `detect_panel(scene) -> quad`，让 `_build_screen.py` 自动检测。

### 6. `build_prompt` 还是模板拼装

现在只是把字段填进模板，没有真正理解需求。
**修法**：两段式——先用 LLM 把自然语言需求解析成结构化字段，再拼模板。

## 已知边界（不算 bug，但要知道）

- 素材质量分是**相对值**，只用于排序，不是绝对画质评价
- 单页界面走整图 base64，单批 ≤ 96MB；批量大图要换直传 + 异步
- 服务只绑 127.0.0.1，没有 token 校验；对外开放前必须加
- 控制台中文乱码是 Windows 代码页问题，`run.ps1` 已切 UTF-8

### 12. 品类词表只覆盖常见电商品类

`pipeline/category.py` 的词表是"护肤 / 口服"两类的经验集合，能准确拦住
「气垫霜配每天一粒」「胶囊配上脸遮瑕」这类明显串台。但：

- 新品类（美容仪、宠物食品、家清、服饰）目前一律 `unknown`，不会误拦也不会拦
- 品类不明的素材（视觉模型判 `other`）不参与冲突判定，只在批次头提示"未校验"
- 纯效果词文案（"保湿补水"）刻意不定性——一个短语就能凑够"两个弱词"，
  按个数判定会把中性文案误判成护肤

**要做的**：接新品类时先补 `_ORAL_STRONG` / `_SKIN_ACT` / `_SKIN_ITEM`，
并给 `scripts/test_category.py` 加 3 条对应用例（该拦的、该放的、中性不误伤的）。
