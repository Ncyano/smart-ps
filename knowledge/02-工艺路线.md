# 02 · 工艺路线（核心方法论）

> **什么时候读**：决定"这类图该怎么生成"之前。**不要跳过这一篇自己重新想做法**——
> 下面每一条都是打了 5–9 轮才定下来的，绕过去的代价是按天算的。

---

## 一、三条总原则

### 1. 分工原则：AI 只做它擅长的

| 交给 AI | 交给代码 | 理由 |
|---|---|---|
| 场景、氛围、光影、人物、材质 | 文字、价格、参数、表格、Logo、版式 | 模型画字必糊，且会冒出违禁词 |
| 生成"另一天"的照片 | 精确的像素级合成 | 合成要可复现、可微调 |

真实案例：模型在瓶身上写出 `MARYANUM (Cannabis Sativa)`（大麻），这是保健品广告的致命错误。
**从那一刻起，所有文字一律后置绘制。**

### 2. 保真原则：商品主体不重绘

`项目方案.md` §6 已定：保真优先 → 抠图 + 透明图层合成，不用图生图整图重画。
只有"场景/氛围"才允许整图生成。

### 3. 数据原则：一切照抄，不编造

价格、含量、专利号、检测数据必须来自真实材料。样张里的品牌和数字都是**示例**。

## 二、决策树：拿到一个需求，先判类型

```
这个需求的核心是什么？
│
├─ 人的变化（肤色、体态、发质）……… 路线 B：img2img 生成"另一天"
│
├─ 环境/氛围（使用场景、生活感）…… 路线 A：文生图（人物场景可用 img2img 保人）
│
├─ 产品本身（瓶/盒/袋主视觉）……… 路线 C：白底渲染 + 抠图 + 代码排版
│
├─ 信息传达（价格/参数/对比表/尺码/成分）
│   └─ 版式为主，图为辅 ……………… 路线 D：HTML/PIL 精确排版
│
├─ 广告位（大屏/灯箱/货架/门店）… 路线 E：空位场景 + 排版 + 透视贴 + 光影融合
│
└─ 证据（检测报告/专利/证书）…… 路线 F：真实素材打底 + 代码标注
```

**混合型很常见**：04 大屏 = A（场景）+ D（排版）+ E（合成）。按顺序串起来做。

## 三、路线 A：文生图（场景/氛围）

**适用**：使用场景、生活感、氛围图、背景板。

**要点**：
1. **先定"这一屏要出现什么"**，再写提示词。分层描述：主体 / 环境 / 光线 / 机位 / 材质。
2. 需要"空位"时，提示词必须写死 `completely blank`、`NO text, NO graphics, NO logos`。否则模型会自作主张填内容。
3. 场景要**正对镜头**时写死：`facing the camera straight on`、`all four edges parallel to the image borders`、`minimal perspective distortion`。

**踩过**：
- 素材是多格拼图时，模型会直接复刻拼图结构 → 先认清素材类型
- 背景复杂（家居杂物）会显得假 → 换成干净墙面

## 四、路线 B：img2img（保人 / 保物）

**适用**：使用前后对比、同一人物换场景、同一产品换环境。

**要点**：
1. `input_fidelity="medium"` 是关键档位。`low` 变化不够，`high` 几乎不变。
2. 提示词描述**变化维度**，同时锁定**不变维度**：`same face shape, same nose/eyes/mouth, same moles` + `remove freckles, even skin tone`。
3. 变化幅度按素材标定，不要凭感觉。减重：躯干正面 5–13%，越往下越大。

**为什么必须做"另一天"**：
一张图调色染色当"使用后"，用户一眼看穿——"除了颜色变化其余一模一样"。
真做一张不同日期拍的照片（机位略远、发型微调、下巴略抬），才可信。

**锐度匹配**：两张源分辨率不同时，把更锐的一侧柔化到同一水平。否则"一边清晰一边糊"，一眼假。

## 五、路线 C：白底渲染 + 抠图（产品类）

**适用**：产品主视觉（瓶、盒、罐）。

**为什么不用商家给的白底图**：
商家的白底 PNG 抠图时，标签的白色高光会被当背景抠掉，出现破洞。实测 swisse / yep 两张都坏了。

**做法**：
1. 用 ImageGen 渲染：`pure white seamless background` + `悬浮无投影` + 标签只做抽象色块（`NO text`）
2. 抠图三坑按顺序处理（见 `03-踩坑库.md` A3）
3. 深色底使用前，再把轮廓 2px 压暗 30%（否则玻璃高光在深色上呈白色锯齿）

**瓶盖必须写死**：
```
宽圆柱形银色铝螺纹盖 / 侧壁竖向滚花 / 盖径略大于瓶口 / 平视机位（看不到瓶口内）/ 悬浮无投影
```
不写死就出白色异形盖——这是反复踩的坑。

## 六、路线 D：代码排版（信息类）

**适用**：价格图、对比表、尺码表、成分介绍、参数页。

**两条技术路线，按精度要求选**：

| 方式 | 优点 | 缺点 | 适用 |
|---|---|---|---|
| **PIL 直接绘制** | 快、无需浏览器、像素级可控 | 排版能力弱，复杂布局难写 | KV 单屏（品牌/标题/徽章/小字） |
| **HTML + CSS + Playwright 截图** | 排版强、好调整、所见即所得 | 需要浏览器、要注意溢出 | 表格、多列对比、长图 |

**PIL 常见坑**：
- `ImageDraw.rounded_rectangle(fill=(0,0,0,0))` 在 RGB 画布上会画成**纯黑块** → 必须用 RGBA 叠加 `Image.alpha_composite`
- 中文必须指定字体文件（`msyhbd.ttc`），`anchor="mm"` 居中

**HTML 常见坑**：
- `td{display:flex}` 会破坏表格布局 → 改 `vertical-align:middle` + `display:inline-block`
- `.row{flex:1}` 会把页面撑高被裁 → 固定 `height:356px`
- 截完必须读 `document.body.scrollHeight` 验证没溢出

## 七、路线 E：透视合成（广告位类）★ 最复杂

**适用**：线下大屏、灯箱、货架、门店陈列。

### 完整流程

```
① 准备空位场景
   生成"正对镜头 + 纯白空白面板 + 深色细边框"的灯箱照
   提示词写死：facing the camera straight on / all four edges parallel to the image borders
              panel completely blank pure white / slim dark frame with inner shadow

② 定框（不靠目测，靠程序）
   a. 亮度 >190 取白色面板区
   b. 从白区边界「向外扫到第一个暗像素 <45」→ 这条暗线是「边框内檐」与「画面开口」的分界
      内檐宽 6–20px，不盖住就会露出一圈浅灰（用户反复圈的就是这个）
   c. 四边各外扩 1.5px，抵消透视插值取整误差
   d. 每条边单独 RANSAC 拟合，内点率 >85% 才采信

③ 出内容
   KV 宽高比 = quad 的实测宽高比（错 1% 文字就明显拉伸）

④ 贴 + 融合（这一步决定成败）
   - 遮罩羽化 0.6px，绝不内缩（内缩 4px = 四边各漏一条原画面）
   - 亮度：lift + ambient + gamma，不要线性抬高（线性抬高 = 整块发灰）
   - 用原屏「低频亮度的比值」调制，保留背光透射的明暗渐变
   - 贴图前先按景深模糊 0.8–1.1px（完全锐利 = 一眼假）
   - 玻璃环境倒影：取屏位旁景物 → 映射到屏面 → 强模糊 → screen 叠加 0.07
   - 边缘 3px 压暗到 0.82 + 背光衰减（灯管在中间，越靠边越暗）
   - 光溢出到周围墙面 spill 0.5

⑤ 落地场景再补两样
   - 接触阴影：底座与地面交接 28px 高斯衰减暗带
   - 地面倒影：取灯箱中下段 560px → 镜像 → 压到地面高度（0.37）→ 渐变模糊 → α 淡出
```

### 判断标准

**缩小到 30% 看，若一眼能指出屏幕轮廓，就是失败。**

"对齐"只占 20%，剩下 80% 是：亮度关系、清晰度匹配、环境反射、边缘过渡。

### 已经固化的脚本

`产出/需求样张/_screen_kv.py`（排 KV + 贴屏）+ `_build_screen.py`（一键构建）+ `_floor_reflect.py`（倒影）+ `_cut_bottle.py`（产品图抠图）。

## 八、路线 F：真实素材打底 + 标注（证据类）

**适用**：检测报告、专利证书、成分介绍。

**铁律：不能生成报告。** AI 造报告 = 造假。

**做法**：拿真实扫描件/翻拍照做底，用代码在上面加：
- 红框标注关键数据
- 引线 + 四字短语（专利号、检测机构、日期）
- 放大镜局部放大
- 数据可视化（曲线、柱状）

**三种已验证的结构**：
1. 报告翻拍 + 红框 + 放大镜（最容易做，证据感最强）
2. 多证书并列成墙（`四大专利 实力认证`）
3. 数据曲线 + 结论句（`28天人体功效实验报告`）

## 九、质检闭环

每类产物都要有**可判定的验收**，不能靠"我觉得还行"。

| 类型 | 验收方式 |
|---|---|
| 前后对比图 | `python scripts/check_compare.py 产出/效果图/*.png`，退出码 0 才交付 |
| 贴屏类 | ① 四角放大自查图 ② 外侧环带 >200 亮像素数必须为 0 ③ 缩小到 30% 看轮廓 |
| 倒影类 | 差分图（加/不加相减），确认衰减到底边无断点 |
| 表格类 | Playwright 读 `scrollHeight` 验证无溢出 |
| 文字类 | 放大 2–3 倍逐字读，确认无乱码/截断 |

**量化优于肉眼**：这个项目里凡是"目测觉得差不多"的地方，后来都被打回。

## 十一、路线 → 模板对照（2026-11-26）

做法已经固化成 `server/app/templates/` 里的模板，产线可 `template=` 选择。
**没进模板的路线不是不重要，是它们的输入形态不同**，见下表最后一列。

| 路线 | 模板 | 覆盖程度 | 还差什么 |
|---|---|---|---|
| A 文生图（场景） | `scene` | ✅ 提示词约束 + 评分 + 导出 | 无 |
| C 白底 + 抠图 | `white_bg` | ✅ 纯白底重排 / 渐变底 grabCut / 纹理底拒绝 | 素材必须是白底或透明 |
| D 代码排版 | `kv` | ⚠️ 只做了"上方文案区"一种版式 | 表格、多列对比、长图（要 HTML+Playwright） |
| B img2img（保人） | — | ❌ | **输入是一对图**（before/after），产线目前是单图出 N 候选 |
| E 透视贴屏 | — | ❌ | 需要场景四角标定 + 透视变换，是 `产出/需求样张/*.py` 那套独立工艺 |
| F 证据类 | — | ❌ | 底线是"不能生成报告"，必须真人拿真实扫描件做，不适合自动化 |

**B 和 E 是下一步要定的**：B 要改成"成对输入"（两张素材 → 一次出双联），
E 要把 `_build_screen.py` 的四角检测封装成 `detect_panel()` 再挂模板。
两者都不是"加个提示词"能解决的，属于改产线形态。

### 模板之间共享的三条红线

1. 文字一律代码绘制，模型不许画字（`kv` 的文案就是 PIL 画的）
2. 主体不重绘（`white_bg` 只做几何重排与抠图，不改产品）
3. 版式必须可判定（`kv` 装不下就报 overflow，降档到 B，不悄悄截断）
