# 自动 P 图产线：素材 + 例图 + 文字 → 成品

日期：2026-11-09　配套：[框架设计](superpowers/specs/2026-11-09-smart-ps-design.md)、[本地模型选型](02-本地模型选型.md)

---

## 0. 需求与三种输入的天然冲突

```
素材图（内容：这个产品/这个人必须一模一样）
往期例图（风格：我们要的是那个味道）
文字修饰（增量：这次要改什么）
        ↓
      成品图
```

这三者不是"拼在一起喂给模型"就能解决的，因为它们互相拉扯：

| 冲突 | 表现 |
|---|---|
| 例图会污染内容 | 模型把例图里的产品、构图、模特一起抄进来 |
| 模型会忽略例图 | 只按文字改，风格完全不像"我们家的" |
| 文字会压过素材 | "换成墨绿色" → 产品形状也变了 |

**结论**：不能把"风格"只交给模型去悟。必须拆成**两条腿**——模型给初稿，确定性后处理保一致。这是本产线的核心设计。

---

## 1. 产线全貌

```
【离线，一次性】
往期例图集 ──▶ 风格蒸馏 ──▶ StyleProfile（参数集）+ 风格参考图（1–3 张）
                                   │                       │
【在线，每批】                      ▼                       ▼
素材图 ──▶ ①分组排序 ──▶ ②参考图打包 ──▶ ③生成 N 候选 ──▶ ④评分筛选
文字 ────▶   指令结构化 ──┘            (Flash 0.12/张)      │
                                                          ▼
                                          ⑤回正到 StyleProfile ──▶ ⑥质检
                                                          │
                                                    成品 / 待人工
```

### ① 分组与排序

- 同一 `Item`（一个产品 / 一个场景 / 一个人物）的素材聚成一组。
- 组内打分：清晰度（拉普拉斯方差）、曝光（直方图截断）、人脸/主体完整性、构图偏差 → 选出**主参考 1 张 + 辅助参考 ≤2 张**（多角度）。
- 废片直接剔除并记录原因，不进生成——**送进去只会拖累保真度**。

### ② 参考图打包（最容易翻车、最该标准化的一步）

多参考模型对**顺序和角色标注**极其敏感，这一层必须是代码，不能靠提示词自觉。

```
pack = [
  {role: "content", image: 主素材,  label: "产品主体，形状/Logo/材质需 1:1 保留"},
  {role: "content", image: 辅素材A, label: "背面细节，仅用于补全不可见部分"},
  {role: "style",   image: 风格参考, label: "仅参考色调、影调、光线质感，不要照搬内容"},
]
```

规则：

- **顺序固定**：内容在前、风格在后；prompt 里用"图 1 / 图 2"指代，不用"上一张"这种模糊说法。
- **数量上限**：内容 ≤3，风格 ≤2，总 ≤5。Seedream Flash 名义支持 10 张，但实测超过 5 张保真度反而下降，不是越多越好。
- **统一尺度**：参考图长边缩到 1280 再上传，省时且无收益损失。
- **风格图要么是蒸馏代表图，要么是"去掉主体"的例图**——直接塞整张例图是污染内容的第一大来源。

### ③ 生成候选

- 默认 **3 候选**，引擎 `seedream-flash`（0.12 元/张）。理由：一次成品的合格率靠"多出几张再挑"比"一次出好"更划算。
- 文字修饰由 Planner 转成结构化指令（见 §3），再拼进 prompt。
- 同一批的所有 Item **共用同一个 StyleProfile 与同一组风格参考图**——这是"成套"的来源。

### ④ 评分筛选

候选逐张算三个分：

| 维度 | 度量 | 不达标处理 |
|---|---|---|
| 风格距离 | 与 StyleProfile 的亮度/对比/色相分布差异（简化版 earth mover 或直方图距离） | 交给⑤回正 |
| 内容保真 | 素材主体区域与成品的 SSIM / 关键点吻合 | 直接淘汰（这条最硬） |
| 技术质量 | 清晰度、噪点、是否出现伪影/文字乱码 | 淘汰或降权 |

选 1 张进⑤，其余留档可换。

### ⑤ 回正到 StyleProfile（确定性的那一条腿）

在**不改变内容**的前提下，把图拉进目标带：

1. 白平衡与整体色偏（按例图的中性灰参考推算色温/色调偏移）；
2. 影调曲线（把亮度直方图对齐到例图分布）；
3. 饱和/对比/高光阴影；
4. 锐化与颗粒（按例图的高频能量标定，避免"AI 塑料感"）；
5. 裁切与主体占比（按例图的构图统计）。

**顺序不能反**：先色再调再锐，最后裁切。每一步都可单步关闭，便于对比与溯源。

### ⑥ 质检与交付

输出两类：

- **可交付**：三个分都过线，附一行"调整摘要"（如"色温 -300K，对比 +8%，主体占比 62%"）。
- **待人工**：附失败原因（"内容保真 0.78 < 0.9：产品 Logo 疑似被重绘"），前端只把这批推给人。

> 这条是整个产品能不能进生产的关键：不是追求"全自动"，而是**让人的注意力只花在真正需要人的那 20%**。

## 2. StyleProfile：产品最该沉淀的资产

从往期例图蒸馏出来的**可量化目标**，不是一张参考图：

```json
{
  "version": 1,
  "source": {"count": 48, "tags": ["白底电商", "美妆"]},
  "tone":   {"luma_p5": 232, "luma_p50": 246, "luma_p95": 252,
             "contrast": 0.82, "highlight_rolloff": "soft"},
  "color":  {"wb_bias_k": -120, "tint": 2.1, "sat_boost": 0.06,
             "hue_shift": {"skin": 1.5, "green": -2.0}},
  "texture":{"sharpen_sigma": 0.8, "amount": 0.45, "grain": 0.02},
  "composition": {"subject_ratio": 0.62, "margin_top": 0.08,
                  "bg": "pure_white", "aspect": ["1:1", "3:4"]}
}
```

用途有三个，缺一不可：

1. **喂给后处理**做回正（⑤）；
2. **喂给评分器**做距离判断（④、⑥）；
3. **喂给 Planner**当"已知目标"，让文字修饰只需要描述增量——用户说"亮一点"，Planner 知道基准是 `luma_p50=246`，该给 +4 而不是 +40。

例图越多越准，但**同一风格的 20–50 张就够稳定**；混入不同风格会把这个 profile 拉垮，所以入库时要能打标签分档。

## 3. 文字修饰怎么进来

三种粒度，从省事到灵活：

| 形式 | 例子 | 处理 |
|---|---|---|
| 全局模板 | "白底，主体居中，保留品牌色" | 直接作为批次级 prompt 前缀，不改 |
| 逐条指令 | "这件换成雾霾蓝，去掉背景里的晾衣杆" | Planner 解析成「改动点 + 保护点」，写进结构化指令 |
| 参数微调 | "再亮一点 / 背景再干净些" | 映射到 StyleProfile 的增量，不重跑生成 |

**Planner 输出的是结构化指令，不是一段自由文本**——因为自由文本里模型容易把"保护点"丢掉：

```json
{
  "must_keep": ["产品形状", "Logo", "材质纹理"],
  "must_change": ["背景 → 纯白", "色温 → 偏冷"],
  "must_avoid": ["改变透视", "添加道具", "改写文字"],
  "engine_hint": "seedream-flash"
}
```

渲染成 prompt 时，`must_avoid` 进负向约束，`must_keep` 显式写进 `role=content` 的标注里。

## 4. 成本模型

| 档位 | 单张成品 | 说明 |
|---|---|---|
| 标准（Flash × 3 候选） | **0.36 元** | 默认 |
| 高清（Pro × 3 候选） | 0.90 元 | 交付级，或标准档不合格时重跑 |
| 中文文字多（Qwen 3.0 × 3） | 0.75 元 | 中文海报/文案类 |
| 后处理、评分、分组 | 0 元 | 全本地 |

批量 100 张 ≈ 36 元起。**候选数可配**：预算紧就 2 张，追求合格率就 4 张。

## 5. 数据结构

```
Batch        一次导入（一批素材 + 一套例图 + 一段文字要求）
 ├ Item      一个成品单元（一个产品/场景），含 1..n 素材、1 个成品
 │  ├ Material   原始素材（含打分、是否被选为主参考）
 │  ├ Recipe     本次生成配置（packing + instruction + engine + n）
 │  └ Candidate  候选图（含三项评分、是否入选）
 └ StyleProfile  本批使用的风格画像（可跨批复用）
```

**可复用性**：`StyleProfile` 与 `Recipe` 都是可命名、可另存的资产。第二次来同一个客户，选上次的 profile + recipe，一键跑完整批。这是产品从"工具"变成"产线"的地方。

---

## 6. 与前面框架的关系

不是推翻，是**补上中间那层**：

- 前面的 Document/Layer、Operator、Engine、Job 全部照用；
- 新增 `Batch / Item / StyleProfile / Recipe` 四个领域对象；
- `⑤回正` 落成一组新的确定性算子（`wb_match` / `tone_match` / `texture_match` / `crop_match`）；
- `④⑥评分` 落成 `ScoreOperator`，本地跑，0 成本；
- 生成仍然走 `Engine` 适配层，路由规则不变（默认 Flash、成品档 Pro、中文档 Qwen）。

**一句话**：素材和例图不是"两张图"，是两个角色；文字不是"提示词"，是一份带保护点的结构化契约。

## 7. 还没定的一条（会改设计）

**例图的粒度**：是"整个店铺/客户共用一套通用风格"（一个全局 StyleProfile），还是"每个商品都带自己的往期成品"（每单一个 profile，甚至要按最近邻检索相似例图）？

- 全局一套 → 蒸馏一次、跑全批，简单稳定；但遇到品类差异（比如白瓷 vs 口红）会拉偏。
- 每单一套 → 更准，但要解决"例图少（3–5 张）时 profile 不稳"和"哪张例图最像这次素材"的检索问题。

两种都能做，但决定了 StyleProfile 是**一个**还是**一族**，以及例图库要不要索引。
