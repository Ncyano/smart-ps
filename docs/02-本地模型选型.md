# 本地轻量模型选型

日期：2026-11-09　配套：[框架设计](superpowers/specs/2026-11-09-smart-ps-design.md) §8、[技术选型](01-技术选型.md)

硬件前提：i5-12600K + Intel UHD 770 核显，无 CUDA。**结论先说**：生成式（文生图/指令重绘）本地不可行，但**修图工作量里 60–70% 的任务本地能做完，且边际成本为 0**。

---

## 1. 先说不可行的，省得反复讨论

| 想做的事 | 本地方案 | 为什么不行 |
|---|---|---|
| 一句话换背景/换风格 | FLUX.2 [klein] 4B（Apache 2.0） | 4B 蒸馏版也要 **~13GB 显存**，核显完全没有机会；纯 CPU 推理一张要分钟级 |
| 高质量指令重绘 | Qwen-Image 系列 / SDXL | 同上，最低门槛 8–24GB 显存 |
| 走 OpenVINO 跑 SD1.5 | fastsdcpu 这类 CPU 方案 | 512² 约 5–15 秒能出一张，但**质量比云端差一个代际**，做演示可以，做产品不行 |

所以本地的定位不是"替代云端"，而是**把不需要生成的那部分全部吃掉**。

---

## 2. 推荐本地模型清单

按修图任务分，每一行都是能装进 `Operator` 注册表的实现。

### 2.1 抠图 / 主体分割（最高频，最该本地化）

| 模型 | 许可 | 体积（约） | CPU 1024² 耗时（估） | 定位 |
|---|---|---|---|---|
| **BiRefNet_lite** | MIT | 90–180 MB | 1.5–4 s | **默认**，发丝级、通用 |
| **BEN2**（Background Erase Network 2） | MIT | 200–400 MB | 2–5 s | 透明物/复杂边缘更好，作精修档 |
| BiRefNet_HR | MIT | 900 MB–1 GB | 5–12 s | 高分辨率整图，后台任务 |
| MODNet | Apache-2.0 | 25 MB | 0.2–0.5 s | 人像视频/实时预览，质量够看不够交 |
| RMBG-2.0 | **非商用需授权** | ~1 GB | 3–6 s | 质量好，但商用要买 BRIA 授权，别默认装 |

**建议**：默认 BiRefNet_lite；用户在预览里不满意时一键切 BEN2 重跑（同一个 `matting` 算子换权重，成本 0）。视频/预览路径用 MODNet。

### 2.2 交互式选区（点一下选中物体）

| 模型 | 许可 | 体积 | 关键工程点 |
|---|---|---|---|
| **SAM 2.1 tiny** | Apache-2.0 | ~150 MB | 编码器 CPU 2–5 s/图，但**只跑一次**；用户每点一下只跑 decoder，几十毫秒 |
| MobileSAM | Apache-2.0 | ~40 MB | 更快更轻，精度略低 |
| SAM 3.1 | Apache-2.0（看具体发布） | 大 | 支持"概念分割"（说"所有杯子"），CPU 偏慢，按需 |

**架构含义**：`segment` 算子必须拆成 `encode(image)` + `decode(points, box)` 两段，编码结果进缓存。这是"点选像 PS 的快速选择工具"能流畅的唯一办法。

### 2.3 擦除 / 补全（去路人、去杂物、去水印）

| 模型 | 许可 | 体积 | CPU 1024² | 适用 |
|---|---|---|---|---|
| **LaMa** | Apache-2.0 | ~200 MB | 2–5 s | **默认**，去物体/去水印，结构延续好 |
| MAT | MIT | ~200 MB | 3–6 s | 大面积、低纹理区域更稳 |
| AOT-GAN | MIT | ~50 MB | 1–2 s | 速度快，纹理弱 |

**边界**：LaMa 擅长"补齐被挡住的背景"，不擅长"凭空造一个沙发"。用户要求"把这块换成 XX"时，那是重绘，走云端。

### 2.4 放大 / 超分

| 模型 | 许可 | 体积 | CPU 1024²→4× |
|---|---|---|---|
| **Real-ESRGAN x4plus** | BSD-3 | 67 MB | 15–40 s（后台任务） |
| Real-CUGAN | MIT | ~10 MB | 3–8 s（动漫/插画更快更好） |
| SwinIR | Apache-2.0 | ~110 MB | 慢，质量高 |

**加速**：Real-ESRGAN 有 ncnn-Vulkan 实现，**UHD 770 核显能跑**，实测常比纯 CPU 快 3 倍以上——这是这台机器上少数能吃到 GPU 的地方。

### 2.5 人脸修复 / 老照片

| 模型 | 许可 | 体积 | 备注 |
|---|---|---|---|
| **GFPGAN v1.4** | Apache-2.0 | ~350 MB | **商用安全**，默认 |
| CodeFormer | **S-Lab 非商用** | ~375 MB | 质量更好，商用要授权，做成可选开关 |
| RestoreFormer++ | Apache-2.0 | ~400 MB | 备选 |

### 2.6 证件照 / 白底 / 尺寸 / 构图

不需要大模型：人脸关键点（YuNet / MediaPipe / InsightFace）+ 抠图 + 规则引擎（尺寸、头肩比、留白、DPI、排版）。**毫秒级**，这是"工具感"最强的一块，也是本地最该做扎实的。

### 2.7 降噪 / 去模糊

NAFNet（MIT，~80 MB）或 SCUNet。CPU 上单张 3–10 s，适合后台批处理。

## 3. 加速路径（这台机器能吃到的三档）

| 路径 | 覆盖模型 | 预期收益 | 备注 |
|---|---|---|---|
| **ONNX Runtime CPU**（默认） | 全部 | 基准 | 最稳，先跑通 |
| **ONNX Runtime DirectML** | CNN 类（超分、修复、抠图、LaMa） | 1.5–3× | UHD 770 支持 DX12，安装包稍大 |
| **OpenVINO** | CNN 类，Intel 官方优化 | 2–3×（同代硬件） | 需模型转换，多一条构建链 |
| **ncnn-Vulkan** | Real-ESRGAN / Real-CUGAN | 3×+ | 仅超分这一路，性价比最高 |

**建议顺序**：先纯 CPU 把整条链跑通并测出真实耗时，再按瓶颈单独换后端——不要一开始就上三层加速，那会把"跑得慢"和"跑挂了"混在一起。

## 4. 本地 vs 云端的分工线（写进产品）

```
本地（0 元，断网可用）                          云端（0.12–0.3 元/张）
─────────────────────────────────────────────  ─────────────────────────────────
抠图/换白底/透明 PNG                            "把背景换成办公室"
点选/框选选区                                   "把沙发改成墨绿色天鹅绒"
去路人/去杂物/去水印                            "给我加一束夕阳侧光"
超分放大/去噪/去模糊                            大幅面重建（>2K 的语义重绘）
修旧照/修人脸                                   文字改写/海报重排
证件照/尺寸/排版/压缩                           风格迁移/多图合成
批量裁剪/水印/边框
```

用户感知应该是：**"能立刻做完的事，它秒回；需要'想'的事，它告诉你花多少钱。"**

## 5. 安装体积预算

只装默认档（L1）：

| 组件 | 体积 |
|---|---|
| BiRefNet_lite | ~150 MB |
| SAM 2.1 tiny | ~150 MB |
| LaMa | ~200 MB |
| Real-ESRGAN x4plus | ~67 MB |
| GFPGAN v1.4 | ~350 MB |
| 人脸关键点 + 规则引擎 | ~20 MB |
| **合计** | **~940 MB** |

可选包（L2）：BEN2、Real-CUGAN、CodeFormer、NAFNet，按需下载。**权重与安装包分离，首次使用某能力才下载**（带校验和、断点续传），否则安装包会变成 3 GB 的灾难。

## 6. 落地到框架里的形式

每个模型都是一个 `Operator`，共享同一套注册与验收：

```python
@register("matting", schema=MattingParams,
          caps=dict(max_px=4096, alpha=True, license="MIT", vram=0))
def matting(ctx, inputs, params):
    model = pick(params.model or "birefnet_lite")   # 换模型 = 换权重，算子不变
    ...
```

验收口径（M1 就要定，别等）：固定 20 张测试图（人像/商品/发丝/透明物/复杂边缘），记录 **PSNR/alpha IoU + 单张耗时**，每次换权重或后端都跑一遍。没有这组基线，后面"本地够不够用"就只能靠感觉吵。

---

## 7. 需要你确认的一条

上面这套本地能力的定位是"默认档"，也就是**断网也应该能交付"抠图+白底+放大+证件照"**。如果你的场景里连这些都必须照片不出本机、且质量要能交付，那 M1 的验收标准要按产品级定（而不是"能跑通"），里程碑也得重排——这和技术选型文档里那条"图片能不能出本机"是同一个问题。
